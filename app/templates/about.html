Cloud Engineering Overview

How TravelGo Works on AWS

TravelGo combines modern frontend simplicity with enterprise-grade AWS services for high availability, security, and real-time responsiveness.

1. Amazon DynamoDB (NoSQL Database)

TravelGo utilizes Amazon DynamoDB for ultra-low latency key-value storage. User accounts are partitioned by email/user_id, while reservations are stored in the travelgo_bookings table. For local offline development and testing, an intelligent local JSON mock driver activates automatically whenever AWS credentials are not configured.

Tables: travelgo_users (Partition Key: email) • travelgo_bookings (Partition Key: booking_id)

2. Amazon SNS (Simple Notification Service)

Whenever a traveler completes a booking or cancels an existing trip, the Python backend invokes boto3.client('sns').publish() to trigger an instantaneous email notice. During local development, an event logger captures all notifications for testing assertions.

Topic ARN: arn:aws:sns:us-east-1:*:travelgo-booking-alerts

3. Amazon EC2 & IAM Instance Profiles

Security best practices dictate never placing AWS access keys inside code or servers. When deployed on EC2, the server inherits permissions automatically via an attached IAM Instance Profile with least-privilege DynamoDB and SNS access policies.

4. Amazon CloudWatch

Application events, search latencies, booking velocity, and error metrics are routed to Amazon CloudWatch logs for live operational monitoring and automated alarms.
